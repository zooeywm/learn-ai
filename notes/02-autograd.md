## 1. 为什么必须先造“自动求导引擎”？

在 Step 01 的 Bigram 模型里，从权重到 Loss 只有一层查表，我们可以手推 `grad = probs - target`。  
但只要网络多叠几层（例如本关的 `Embedding → MatMul → Add → ReLU → MatMul → Add → CrossEntropy`，以及后面第 3、4 关的 Self-Attention 和多层 Transformer）：

- 每次改一下网络结构，手推整网梯度都会变成一场灾难；
- 哪怕漏写一个负号、转置错一个维度，模型就会静悄悄地学不出来。

**PyTorch / JAX 最核心的魔法就是 Autograd（自动求导）**：  
你只需要像搭积木一样写出**前向传播（Forward）**，框架会自动记下每一步算了什么（形成**计算图**），然后调用一行 `backward(loss)`，沿着计算图**倒着走一遍链式法则**，把每个参数的梯度全算出来。

## 2. 最契合 Rust 的计算图设计：Arena Tape（磁带模式）

如果在 Rust 里照搬 Python 的面向对象写法（每个节点拿 `Rc<RefCell<Node>>` 互相指），代码会写满 `.borrow_mut()`，又丑又慢。

本关采用 Rust 里最优雅的 **Arena Tape（线性磁带）** 模式：

```rust
#[derive(Clone, Copy)]
struct TensorId(usize);   // 张量句柄只是一个数组下标！随意 Copy，零借用冲突

struct Node {
    rows: usize,
    cols: usize,
    data: Vec<f32>,       // 前向算出来的矩阵值
    grad: Vec<f32>,       // 反向传播累加的梯度 d(Loss)/d(data)
    op: Op,               // 记录这个节点是怎么算出来的（父节点是谁）
}

struct Tape {
    nodes: Vec<Node>,     // 所有节点按创建顺序平铺在一个 Vec 里
}
```

**这个设计有一个极其优雅的副产品——天然拓扑序**：
- 因为你只能用**已经创建好的父节点**去算出子节点，所以子节点在 `Vec` 里的下标**永远大于**它的所有父节点；
- 因此执行反向传播 `tape.backward(loss_id)` 时，根本不需要写递归 DFS 拓扑排序，直接把 `Vec` **从后往前倒着遍历**即可：

```rust
self.nodes[loss_id.0].grad[0] = 1.0;          // d(Loss)/d(Loss) = 1
for id in (0..=loss_id.0).rev() {             // 天然逆拓扑序！
    // 按 self.nodes[id].op 的局部导数，把 grad 累加回父节点
}
```

> **核心注意点（为什么要 `+=` 而不是 `=`）**：  
> 在计算图里，同一个变量（比如权重矩阵、或残差连接里的 `x`）可能被**多条分支同时使用**。根据多元微积分链式法则，多条路径传回来的梯度必须**相加累加（`+=`）**，绝不能互相覆盖！

## 3. 本关 6 个基础算子的前向与反向规则

设当前节点输出为 $Y$，下游已经传回来的上游梯度记为 $dY = \frac{\partial \mathcal{L}}{\partial Y}$：

### 3.1 `Add`（加法 + 偏置行广播）
- 前向：$Y = A + B$（支持同形状，也支持 `(R, C) + (1, C)` 把偏置行加到每一行）。
- 反向：**加法是梯度路由器**，把 $dY$ 原样复制分给两条分支：
  - $dA \mathrel{+}= dY$
  - 若 $B$ 是 `(1, C)` 广播来的，则把所有行上的 $dY$ **沿行求和**累加进 $dB$。

### 3.2 `Mul`（逐元素乘法）
- 前向：$Y = A \odot B$。
- 反向：**乘法是梯度交换器**，乘上“另一边的前向值”：
  - $dA \mathrel{+}= dY \odot B$
  - $dB \mathrel{+}= dY \odot A$

### 3.3 `MatMul`（矩阵乘法 —— 所有大模型的发动机）
- 前向：$Y_{(M, N)} = A_{(M, K)} \cdot B_{(K, N)}$。
- 反向（记住最简单的“**维度配平法则**”就永远不会忘）：
  - 想求 $dA$（形状 $M \times K$），手里有 $dY_{(M, N)}$ 和 $B_{(K, N)}$，唯一能拼出 $M \times K$ 的乘法就是：
    $$dA \mathrel{+}= dY \cdot B^\top$$
  - 想求 $dB$（形状 $K \times N$），手里有 $A_{(M, K)}$ 和 $dY_{(M, N)}$，唯一能拼出 $K \times N$ 的乘法就是：
    $$dB \mathrel{+}= A^\top \cdot dY$$

### 3.4 `ReLU`（非线性激活函数）
- 前向：$Y = \max(0, X)$。
- 反向：**梯度单向阀门**——
  - 前向 $X_i > 0$ 的位置，导数为 `1`，梯度原样放行：$dX_i \mathrel{+}= dY_i$；
  - 前向 $X_i \le 0$ 的位置，导数为 `0`，梯度被彻底截断（归零，这就是“神经元死亡 / Dead ReLU”现象）。
- **为什么一定要加非线性激活？** 如果没有 ReLU，两层线性矩阵乘法 `(x @ W1) @ W2` 在数学上等价于 `x @ (W1 @ W2)`，叠一万层也只相当于一层！

### 3.5 `EmbedConcat`（词向量查表 + 拼接）
- 不再用巨大的 `V × V` 表，而是给词表里的 373 个字每人分配一个低维“语义坐标向量”（本关 `emb_dim = 24`），组成词嵌入表 `emb (V, 24)`。
- 每次看前 3 个字，查出 3 个 24 维向量拼成 72 维输入送进网络。
- 反向：把对应的梯度切片累加回词表里对应字的那一行（Scatter-Add）。

### 3.6 `CrossEntropy`（Softmax + 交叉熵损失）
- 沿用 Step 01 的经典导数公式：$dZ_{b, j} \mathrel{+}= \frac{p_{b, j} - \mathbb{I}(j = y_b)}{B} \cdot d\mathcal{L}$。

## 4. 本关额外引入的两个实战标配

1. **随机高斯初始化（He Init）**：
   - 在 Step 01 里权重可以全 0 初始化；但在多层神经网络里，如果 `W1`、`W2` 全为 0，所有隐藏层神经元算出来的激活和梯度完全一模一样，永远学不出不同特征（**对称性破缺失败**）。所以必须用均值为 0、标准差约 $\sqrt{2 / d_{\text{in}}}$ 的小随机数初始化。
2. **AdamW 优化器**：
   - Step 01 用的是纯 SGD，学习率很难调（太小走不动，太大炸掉）。
   - **AdamW** 为每个参数维护一阶动量 $m$（梯度的滑动平均，像滚下山的惯性）和二阶动量 $v$（梯度平方的滑动平均，自动给梯度大的参数缩小步长、给梯度小的参数放大步长），再加上解耦权重衰减（Weight Decay），是现代几乎所有 LLM 训练的默认优化器。

| 收敛后 Loss | 卡死在 `1.2517` | **暴降到 `0.0120`** |

再看训练后的真实生成结果：
```text
「秦时明」-> 秦时明月汉时关，万里长征人未还。但使龙城飞将在，不教胡马度阴山
「春眠不」-> 春眠不觉晓，处处闻啼鸟。夜来风雨声，花落知多少。
「床前明」-> 床前明月光，疑是银河落九天。 / 朝辞白帝彩云间，千里江陵一日还。
```

**仔细看最后一句特别精彩的现象**：
- 为什么「床前明月光，疑是」后面突然接成了李白另一首诗的「银河落九天」？
- 因为我们的 MLP **只看前 3 个字**！当滑动窗口走到 **`，疑是`** 时，《静夜思》的「床前明月光，疑是地上霜」和《望庐山瀑布》的「飞流直下三千尺，疑是银河落九天」拥有**一模一样的 3 字上下文 `，疑是`**，窗口早已把更早的「床前明月光」滑丢了！
- 而且如果硬把 MLP 窗口拉长到 1000 个字，`W1` 参数量会直接爆炸，还无法动态聚焦远处的关键字。

**这就是下一关 Step 03 引入 Self-Attention（自注意力机制）的真正原因！**
